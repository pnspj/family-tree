## 1. データ形式

### 1.1 保存・エクスポート単位 `FamilyFile`

```ts
interface FamilyFile {
  format: 'family-tree';   // 識別子（インポート時の判定に使う）
  version: 1;              // スキーマのバージョン（将来のマイグレーション用）
  persons: Person[];       // 配列の順番 ＝ 登録順
  unions: Union[];
  settings: Settings;
}
```

### 1.2 人物 `Person`

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | string | `crypto.randomUUID()` で採番する |
| `familyName` / `givenName` | string? | 姓 ／ 名 |
| `familyNameKana` / `givenNameKana` | string? | みょうじ ／ なまえ |
| `birthFamilyName` / `birthFamilyNameKana` | string? | 旧姓 ／ 旧姓（かな） |
| `nickname` | string? | 呼び名（例：大阪のおばあちゃん） |
| `gender` | `'M' \| 'F' \| 'O'`? | 男 ／ 女 ／ 他（未入力も可） |
| `genderLabel` | string? | `'O'` のときの自由入力 |
| `birth` / `death` | PartialDate? | 生年月日 ／ 没年月日（年のみ・年月のみも可） |
| `deceased` | boolean? | 没年月日が不明なときだけ使う死没フラグ |
| `childOf` | string? | 親の Union の ID（親が未登録なら持たない） |

```ts
interface PartialDate { y: number; m?: number; d?: number }  // m を持つなら y 必須、d を持つなら m 必須
```

- **死没かどうか** は `death があるか、または deceased === true` で判定する。没年月日を入力すれば自動的に「死没」扱いになるので、フラグは保存しない。
- 入力項目に必須はない。名前がなくても、関係だけで家系図に表示できる。

### 1.3 婚姻ユニット `Union`

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | string | |
| `partners` | `[string \| null, string \| null]` | 2人の Person ID。片方または両方が未登録でもよい |
| `status` | `'current' \| 'former'` | 現在の婚姻 ／ 元（離婚など） |

- 親子関係は **子の `childOf` だけ** に持つ。Union 側に子の一覧は持たない（データの重複と不整合を防ぐため）。
- 同じ親から生まれた子が「きょうだい」になる。異父・異母きょうだいは、片方の親だけを共有する別の Union の子として表現される。

### 1.4 設定 `Settings`

| 項目 | 型 | 説明 |
|---|---|---|
| `egoId` | string? | 続柄の起点になる人物 |
| `labelOverrides` | `Record<labelId, { kanji?, kana? }>` | 家庭ごとの呼び方の上書き（例：`father → { kana: 'パパ' }`） |

表示の ON/OFF（ひらがな表示、マスク、生没年など）は、閲覧する端末ごとの好みなので FamilyFile には含めず、localStorage に保存する。

## 2. 不変条件（保存・インポート時に検証する）

1. ID はファイル内で一意である。
2. `childOf`・`partners` が指す ID は実在する。
3. 1つの Union の `partners` に同じ人物は入らない。
4. 1人が partner になる Union は **最大2つ**（3人以上との婚姻はスコープ外）。
5. 同じ2人の組み合わせの Union は1つだけ。
6. **循環がない**（自分が自分の祖先にならない）。
7. 空の Union（partners が両方 null）は、子が2人以上いる場合だけ存在できる。これは「親は不明だが、きょうだいであることは分かっている」状態を表す。
   - partners が両方 null で子が1人以下、または、partners が null で子がいない Union は、自動で削除する。

## 3. 編集操作

すべての操作は「既存の人物から追加する」形で行う。これにより、家系図がつながった1つのまとまりのまま保たれる。

| 操作 | 処理 | 失敗する条件 |
|---|---|---|
| 親を追加 | `childOf` がなければ Union `[新しい人, null]` を作る。あれば空いている枠に入れる | 親がすでに2人いる |
| 配偶者を追加 | Union `[本人, 新しい人]` を作る（status は current） | 本人の Union がすでに2つある |
| 子を追加 | 本人の Union を選び、新しい人の `childOf` にする。Union がなければ `[本人, null]` を作る | — |
| きょうだいを追加 | 本人の `childOf` と同じ Union を新しい人に設定する。本人に親がなければ空の Union を作り、2人とも子にする | — |
| 婚姻の状態を変更 | current と former を切り替える | — |
| 親を付け替え（つながりを直す） | `childOf` を既存の別の Union に変える、または外す。変更後に空になった Union は不変条件7 に従って整理する | 自分が partner の Union を選んだ場合、循環ができる場合 |
| 登録済みの人と婚姻 | 2人の間に Union を作る。片方に「相手が未登録の親」の Union があれば、その空いた枠に入れる | 同じ2人の Union がすでにある、どちらかの Union が2つある |
| 人物を削除 | partners から外して null にし、本人の `childOf` も消す。その後、不変条件7 に従って Union を整理する | 削除すると家系図が分断される場合は警告を出す（禁止まではしない） |

## 4. 導出値

### 4.1 きょうだいの並び順

1. 生年月日の早い順。年だけ・年月だけの入力は、その期間の最初の日として扱う。
2. 生年月日がない人は最後。
3. 同じなら登録順（`persons` 配列の順番）。

レイアウト上の扱い：

- 血筋側のきょうだいは、上の順番を厳守する。
- 婚姻で来た人は、配偶者の隣に置くことを優先する。そのため、その人の実家のきょうだいの中では順番が崩れることがある。

### 4.2 年齢と死没の表示

- **年齢**：満年齢で計算する。年だけ・年月だけの入力は、欠けている月・日を「1」とみなす。
  - つまり、年だけなら1月1日に、年月だけならその月の1日に1歳加わる。
- **生存している人**：今日を基準に「◯歳」と表示する。
- **死没した人**：生年月日と没年月日が両方あれば「満◯歳で没」と表示する。
  - 没年月日が不明（`deceased` フラグだけ）の場合や、生年月日がない場合は表示しない。

## 5. 続柄判定

### 5.1 キーの書き方

「起点の人（ego）から見て、対象の人（target）がどういう関係か」を、次のキーで表す。

| 表記 | 意味 |
|---|---|
| `B(a,b)` | 血族。最も近い共通の祖先まで a 世代上がり、b 世代下がる。（a+b が親等） |
| `S+B(a,b)` | ego の **現在の配偶者** の血族 |
| `B(a,b)+S` | ego の血族の **現在の配偶者** |
| `S` ／ `S(former)` | ego 自身の配偶者 ／ 元配偶者 |

- `B(1,1)` は、親を1人でも共有していればきょうだいになる。そのため、異父・異母きょうだいも「兄」「妹」などで表示される。
- 姻族は **現在の婚姻だけ** をたどる。元配偶者の親族は、後で説明する経路表示になる。

### 5.2 判定の優先順位

1. 本人なら `B(0,0)`。
2. ego と target の間に Union があれば `S` または `S(former)`。
3. 血族の関係がマスターにあれば `B(a,b)`。
4. 姻族の候補（`S+B` と `B+S`）のうち、親等が近いものから順にマスターを引き、最初に見つかったもの。
5. 4までで見つからなければ **経路表示**（5.5）。関係がまったくなければ表示しない。

例として、いとこ同士で結婚している場合は 2 の「夫」「妻」が優先される。

### 5.3 性別と年齢による使い分け

**性別**：`M` ／ `F` ／ `N`（他または未入力）の3つで行を選ぶ。N の行は、性別を問わない言い方（親、きょうだい、パートナーなど）にしている。

**年齢比較**：比較の相手は「関係をたどる途中で、target と同じ世代にいる ego 側の人」と決めている。この1つのルールで、次のすべてをまかなえる。

- きょうだい・いとこ：本人と比べる。
- 伯父・叔父：本人の親と比べる。
- 大伯父・大叔父：本人の祖父母と比べる。
- 義兄・義弟（配偶者のきょうだい）：配偶者と比べる。
- 兄嫁・姉の夫などの `B+S`：対象本人ではなく、血のつながったきょうだい側（兄・姉）と比べる。

生年月日の精度が足りずに判定できない場合（片方が未入力、1980年と1980年5月の比較など）は、「不明」の行を使う。例：兄弟、おじ。
生年月日が完全に一致する場合（双子など）は、登録が先の人を年上とする。

**表示の切り替え**：年齢で使い分けるのは漢字だけで、子供向けのひらがなは同じ言い方になる。

- 伯父・叔父 → どちらも「おじさん」
- 従兄・従妹など → どちらも「いとこ」

### 5.4 父方・母方

`B(a≥1, …)` の関係については、最初にたどる親の性別から `side: paternal / maternal` を返す。
「父方の祖父」「おとうさんがわの おじいさん」のような補足表示に使える（表示するかどうかは、表示オプションで切り替える）。

### 5.5 経路表示（マスターの範囲外）

ego から target への最短経路（親・子・配偶者の各辺を1歩と数える）をたどる。その経路を **先頭から、マスターに載っている最も長い区間で区切り**、それぞれのラベルを「の」でつなげる。

| 例 | 漢字 | ひらがな |
|---|---|---|
| 祖母の弟の子（5親等） | 大叔父の息子 | おおおじさんの むすこ |
| 父の元配偶者 | 父の元妻 | おとうさんの もとの おくさん |
| いとこのいとこ | 叔父の妻の姪 | おじさんの おくさんの めい |
| 妻の兄の妻 | 妻の兄の妻 | おくさんの おにいさんの おくさん |

- 経路表示をせずに非表示にすることもできる（`pathFallback: false`）。これは表示オプションで切り替える。
- `labelOverrides` は経路表示の各部分にも反映される。例：「パパの もとの おくさん」。

### 5.6 ふりがな表示

各ラベルの読みがなは、ラベル ID ごとに `{漢字|よみ}` という記法で持つ（例：`{大叔母|おおおば}`、`{親|おや}のきょうだい`）。
- 読みがなの元の文字列は、漢字のラベルと完全に一致する（テストで保証）。
- 経路表示では、各部分の読みがなを「の」でつなぐ。
- 漢字を上書きした場合、その読み方は分からないため、ふりがななしで表示する。

### 5.7 呼び方の上書き

マスターの各行は `id` を持っている。`settings.labelOverrides[id]` で、漢字・ひらがなをそれぞれ上書きできる。
同じ id は、どのキーでも同じ言い方になるように揃えてある（テストで保証）。例：`uncle_elder` は `B(2,1)`・`S+B(2,1)`・`B(2,1)+S` で共通。

### 6.1 マスターに入れていないもの（経路表示になる）

- 5親等以上の血族：いとこの子、祖父母のきょうだいの子、高祖父母のきょうだいなど
- 甥・姪・いとこ・孫以下の配偶者（例：甥の妻 → 経路表示で「甥の妻」）
- 配偶者の祖父母のきょうだい、配偶者のいとこなど
- 相婿（あいむこ）・相嫁（あいよめ）など、配偶者のきょうだいの配偶者
- 元配偶者を経由する関係

## 7. 保存とインポート

| 機能 | 方式 |
|---|---|
| 自動保存 | IndexedDB に FamilyFile を丸ごと保存する（変更のたびに、0.4秒待ってまとめて保存）。現状は1ブラウザにつき1つの家系図。複数の家系図を持つ場合は、キーを家系図ごとの ID に変える |
| エクスポート | FamilyFile を JSON でダウンロードする |
| インポート | `format` と `version` を確認し、不変条件を検証する。違反があれば読み込まずにエラー内容を表示する |
| バージョン管理 | `version` を上げたら、`migrate(v → v+1)` の関数を順に適用する |

## 8. 決定事項（旧：未決事項）

- **双子の兄・弟の判定**：生年月日が同じ場合の判定を「登録順」としたが、それでよいか。別案は、出生時刻や長幼の項目を追加すること。
- **継子・継父・継母の言い方**：漢字は継子／継父／継母、ひらがなは「ぎりの〜」とした。家庭によっては避けたい言い方かもしれないので、上書きで対応するか、既定値を変えるか。
（以上3点は確定済み。双子は登録順、継子などの言い方と N の言い方は既定値のまま、家庭ごとの上書きで対応する）
